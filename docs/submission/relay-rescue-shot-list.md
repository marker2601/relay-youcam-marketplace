# Relay Rescue production shot list

Capture at 1440×900 or larger unless a mobile frame is specified. Use the existing synthetic, consent-safe shopper image and project-owned garment assets. Keep browser developer tools, credentials, task IDs, object keys, signed URLs, and unrelated third-party marks out of every frame.

## 1. Reliability promise

- **State:** Signed out on the production home page.
- **Frame:** Relay mark; both exact promise sentences; the primary/backup mechanism sentence; and both marketplace entry actions.
- **Proof:** A judge understands within five seconds that Relay protects a time-sensitive fashion outcome.
- **Suggested alt text:** “Relay home page promising a primary look, backup look, and owner confirmation for time-sensitive fashion.”

## 2. Primary and independent backup

- **State:** Shopper shortlist after at least two real/final previews are ready.
- **Frame:** Primary and Backup headings, different provider names, both YouCam results, readiness totals/components, event countdown, and the appearance-not-fit disclaimer.
- **Proof:** The plan is intentionally resilient and YouCam is integrated into both options.
- **Privacy:** The consented synthetic shopper may appear; no URL query string or developer data should be visible.
- **Suggested alt text:** “Relay shortlist with YouCam previews for a primary look and an independent-provider backup, each with readiness components.”

## 3. Failure becomes recovery

- **State:** The primary provider has declined; shopper reservation page shows **Backup available**.
- **Frame:** Status heading, backup title/provider, and **Activate backup look** action; include the no-payment disclosure.
- **Proof:** Relay retains an actionable plan after the first choice fails.
- **Suggested alt text:** “Relay shopper timeline offering one-tap backup activation after the primary owner declines.”

## 4. Event ready

- **State:** Backup provider accepted; shopper refreshed to the superseding reservation.
- **Frame:** **Event ready** heading, Backup request label, event/pickup/return context, and no-payment disclosure.
- **Proof:** A different provider completes the recovery journey.
- **Suggested alt text:** “Relay timeline in Event ready state after the independent backup provider accepts.”

## Optional supporting frames

- Provider request showing urgency and countdown while omitting source media and measurements.
- Mobile primary/backup comparison with no horizontal overflow.
- Privacy and image-deletion panel with Relay and upstream retention explained separately.

## Thumbnail composition

Use project-owned visuals only. Place the Relay wordmark and short line **Primary fails. Backup is ready.** beside a clean crop of the paired primary/backup cards. Do not imply guaranteed fit, delivery, or availability, and do not place YouCam or Perfect Corp. logos beyond nominative text already present in the product.

## Final asset QA

- [ ] All required states come from the final production commit.
- [ ] At least one visible result used the real YouCam Clothes v3 path.
- [ ] Primary and backup providers are demonstrably different.
- [ ] Text is readable at Devpost preview size.
- [ ] No personal photo, secret, signed URL, object key, or developer console is visible.
- [ ] Every screenshot has concise alt text in the submission.
